# Происхождение и исправления

Версия 1, 7 ноября 2026. Рабочие процедуры написаны для FAMILY REHAB на основе требований владельца, сопоставления открытого SEO Audit и проверки официальных справок. Курс — дополнительный материал, не источник обязательных правил. Доступ к NotebookLM в рабочем процессе не нужен.

## Материалы подготовки

- Исходный 01.txt: реестр 32 строк при заявленных 33 источниках, без URL видео.
- Ответ NotebookLM о семантике: вложение cda773f3-da35-495b-9c72-fadac1787020.
- Ответ NotebookLM о GSC/GA4/GTM: вложение 316944a8-9724-4051-999c-adbc72080eaa.
- https://github.com/coreyhaines31/marketingskills/tree/main/skills/seo-audit — изучены основной файл, local-seo.md, rankings-push.md, title-tags.md. GitHub-материал тоже содержит чрезмерно категоричные эвристики; не импортирован целиком. Лицензия источника сохранена в LICENSE.upstream.

Числовые ссылки NotebookLM и названия уроков не позволяют проверить видео без оригинальных URL/транскриптов. Не приписывай автору точные цитаты как проверенный факт. Маркер [suspicious link removed] в последнем ответе не является адресом Sitemap; точный адрес получать из GSC или доступных файлов.

## Принятые решения

| Совет материала | Решение |
|---|---|
| Sitemap сам станет успешным за сутки | Не принимать; диагностировать точный URL и последнюю попытку чтения, причина сейчас неизвестна |
| site: подтверждает полную индексацию | Использовать лишь дополнительно; основной источник — URL Inspection |
| Если URL нет в Google, сразу запросить индексацию | Сначала причина исключения и доступность |
| Container Loaded означает исправную GA4 | Только признак загрузки контейнера; нужен факт получения события правильным ресурсом |
| Событие обязательно появится за минуту | Не гарантировать; DebugView, ресурс, согласие, блокировки и запросы |
| Всем тегам Once per page | Отвергнуть как универсальную дедупликацию; спроектировать событие по смыслу действия |
| Клик или страница спасибо = обращение | Разделить взаимодействие, подтверждённую отправку и разговор |
| Показы без кликов = плохой description | Сначала позиция, объём данных, запрос, устройство, состав выдачи |
| Нужен SSR для индексации React | Проверять рендеринг и содержание; Google выполняет JavaScript |
| Совпадение запроса у двух страниц требует слияния | Не сливать без доказанной проблемы и оценки отдельных потребностей |
| Нет понятной причины отставания → нужны ссылки | Неизвестное оставить неизвестным; не назначать закупку ссылок |

Официальные источники каждой процедуры указаны в соответствующем справочнике. Новые интерфейсы и изменившиеся политики перепроверять на момент применения; сохранённая дата проверки не обещает вечную актуальность.

Дополнительные ограничения: не применять схемы покупки ссылок ради ранжирования, пропорции анкоров, манипулятивные дроп-домены или массовые малоценные страницы. Основание: https://developers.google.com/search/docs/essentials/spam-policies

## Поведенческая приёмка версии

Проверить на ситуациях: (1) 200 + успешный Live Test + ошибка Sitemap → не выдумывать причину; (2) нет доступа GA4 → короткое задание владельцу, не заявление «аналитики нет»; (3) желание пяти страниц → обоснование каждой, не автоматическая генерация; (4) два настоящих действия в SPA → не подавлять второе глобальным Once per page; (5) локальный код при недоступном сайте → не выдавать за живой аудит; (6) готовый промпт → не публиковать самостоятельно.
