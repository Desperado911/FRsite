# Измерение обращений

## Сначала определить событие

Различай клик по tel:, переход в WhatsApp, успешное получение формы системой, состоявшийся разговор и квалифицированное обращение. Клик и открытие страницы «Спасибо» сами по себе не доказывают получение заявки. Не присваивай всем действиям единый показатель «лиды».

Названия тегов из курса — примеры, не обязательный стандарт. Сначала изучи реально настроенные события. Не устанавливай второй GA4/GTM без проверки существующего подключения.

## Карточка: подключена ли аналитика

Самостоятельно: найди подключение в коде, в опубликованном HTML/DOM и сетевых запросах, если доступны. Наличие скрипта не подтверждает получение события нужным ресурсом GA4.

Задание владельцу при наличии GTM: «Открой нужный контейнер → Workspace / Рабочая область → Preview / Предварительный просмотр → адрес сайта → Connect. Верни статус подключения и сведения о сработавшем Google-теге, без данных посетителей».

Если GTM нет, используй Tag Assistant для существующего Google tag; отсутствие GTM само по себе не ошибка. Preview может запускать неопубликованный черновик: отметь, какая версия проверяется, и отдельно проверь опубликованную после разрешённого изменения.

Источник: https://support.google.com/tagmanager/answer/6107056

## Карточка: получение события

Одно небольшое задание: подключить отладку своего устройства, выполнить одно согласованное действие и открыть GA4 → Администратор → Отображение данных / Data display → DebugView. Вернуть имя события, время и количество появлений. Realtime — дополнительная проверка.

Не отправляй реальные тестовые заявки или сообщения сам без разрешения. Для форм предложи владельцу согласованный тест без медицинских и персональных данных.

Цепочка свидетельств: действие → триггер → тег в Tag Assistant → событие в нужном GA4. Tags Fired не доказывает приём GA4. Если события нет, проверь совпадение ресурса, debug mode, согласие на аналитику, блокировщики и запросы; не отключай защиту конфиденциальности ради результата. Не обещай появление ровно за минуту.

В GA4 используется термин key event / ключевое событие. Отметка важности не исправляет неверный триггер. Для Google Ads конверсии — отдельная настройка, не включать её без задачи.

Источники: https://support.google.com/analytics/answer/7201382 и https://support.google.com/analytics/answer/12571843

## Проверка дублей — правило нашего проекта

Не устанавливай Once per page всем тегам. Это ограничение срабатываний в пределах загрузки документа, не дедупликация обращений; в SPA может подавить последующее самостоятельное действие, а перезагрузка не защищена.

Проектируй событие успешной формы по подтверждению обработки, а не только клику. Перед реализацией определить транспорт формы и где возникает подтверждение. При необходимости использовать внутренний идентификатор успешной отправки без персональных данных; не предполагать автоматическую дедупликацию произвольных GA4-событий.

Критерии теста: успешная отправка → одно событие; ошибка/невалидная форма → ноль событий успеха; двойной клик одной отправки → один успех; новая самостоятельная успешная отправка → новый успех; перезагрузка не создаёт ложную заявку. Это критерии реализации, не утверждение о текущем сайте.

Источник о firing options: https://support.google.com/tagmanager/answer/6279951
Данные посетителей не передавать в GA4: https://support.google.com/analytics/answer/6004245

## Карточка: результат SEO

Попроси GSC → Эффективность / Результаты поиска → тип поиска Web → последние завершённые 28 дней и сопоставимый предыдущий период. Для нового сайта без достаточной истории используй доступный период и обозначь ограничение. Вернуть фильтры, даты и выгрузки запросов/страниц с кликами, показами, CTR и средней позицией. Для анализа пары запрос–страница применить соответствующий фильтр; не соединять две агрегированные таблицы как будто это пары.

Разделяй брендовые и небрендовые запросы, страны и устройства; GSC не считать отчётом по точным позициям во всём Алматы. Учитывай неполноту списка запросов. Мало показов или нет кликов → сначала позиция, намерение, состав выдачи, объём данных; не менять title автоматически.

Сопоставь Google organic в аналитике с подтверждёнными обращениями по доступной атрибуции; заяви её ограничения. GSC-клик и GA4-сеанс не обязаны совпадать. Храни дату изменения и исходные значения. Срок наблюдения выбирай по трафику и переобходу; не гарантируй эффект через фиксированные 2–4 недели.

Источник: https://support.google.com/webmasters/answer/7576553
